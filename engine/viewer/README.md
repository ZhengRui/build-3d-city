# City viewer engine

The browser viewer of `build-3d-city`, the same for every city: three.js (WebGPURenderer, falling back to WebGL 2)
from a pinned CDN import map (or a vendored copy, `vendor/`), ES modules, no build step. A city is a small folder that points at this engine:

```
demos/<city>/web/
  city.json      the city: title, About text, latitude and season of the sun, wind, conventions (below)
  index.html  -> ../../../.agents/skills/build-3d-city/engine/viewer/index.html   (tracked symlink)
  engine      -> ../../../.agents/skills/build-3d-city/engine/viewer              (tracked symlink)
  tiles blocks markings trees shores cars rooftops lamps -> ../../data/<city>/<name>   (git-ignored symlinks)
```

Serve that folder and nothing else (`python3 -m http.server` follows the links):

```sh
python3 -m http.server 8770 --bind 0.0.0.0 -d demos/<city>/web
# open http://<host>:8770/   (?view=<preset name>, ?at=x,z,distance,elevation, ?time=21, ?webgl=1 for the WebGL 2 backend ...)
```

Paths here assume the default project layout: the skill at `<project>/.agents/skills/build-3d-city/`, a city's
config at `<project>/demos/<city>/`, its data at `<project>/demos/data/<city>/`; adjust the relative links if yours
differs. Worked `city.json` files of seven cities are in `../../examples/<city>/web/city.json`.
How the viewer works inside (render loop, frame kinds, shader preparation, test handles):
`../../references/viewer-architecture.md`.

## Start a new city's web folder

```sh
mkdir -p demos/<city>/web && cd demos/<city>/web
ln -s ../../../.agents/skills/build-3d-city/engine/viewer engine
ln -s ../../../.agents/skills/build-3d-city/engine/viewer/index.html index.html
for n in tiles blocks markings trees shores cars rooftops lamps; do ln -s ../../data/<city>/$n $n; done   # (the pipeline's link_web does these)
cp ../../../.agents/skills/build-3d-city/examples/<nearest city>/web/city.json . && $EDITOR city.json
```

Start from the example city nearest in type (`../../examples/README.md`), then change at least `title`,
`nativeTitle`, `about`, `storagePrefix` (unique per city: two cities on one host otherwise share remembered
settings), `location`, `sun`, `time` (`utcOffset`, `zone`, presets), `water.windFrom`; drop the example's
city-specific tuning (landmark glows, `night.*` opt-ins, `facade.styles`) until your own views call for it. List the
data links in `demos/<city>/.gitignore` (`web/tiles` ... `web/blocks`, `web/lamps`); `city.json`, `index.html` and
`engine` are tracked. `tiles/` is required; every other data folder is optional (the viewer runs without blocks,
markings, trees, shores, cars, rooftops or lamps, and hides their switches).

What a visitor sees at the start, whatever the city (each choice is remembered per browser once changed): the menu
folded (the city first), the Stats line hidden (`features.stats`), trackpad mode on (two-finger scroll pans, pinch
zooms; a mouse wheel is recognised by its first event of a burst and still zooms), occlusion with its far fade on
the scene camera (`ao.cameraDepth`), and the blue hour's grade at dusk (`night.duskGrade`).

What the viewer takes from the pipeline's data rather than from `city.json`: the scene frame, extent and preset views
(`tiles/tiles.json`: `views` with `group` Areas/Landmarks, `extent`, `ground`, `terrain`, `styles`, `floor`,
`uvRange`, `moduleMax`), the markings' frame (`markings/markings.json`), tree classes (`trees/trees.json`), car types,
sizes and colour palettes (`cars/cars.json`), rooftop materials, palette and styles (`rooftops/rooftops.json`),
shore types (`shores/shores.json`), blocks (`blocks/blocks.json`). Which side traffic drives on is in the cars'
lanes and the markings, so the viewer needs no setting for it.

A preset view may carry an hour (`time`, from `[views.areas]`' seventh number): choosing its chip moves the time
slider there as the Day/Dusk/Night shortcuts do, and `?view=<it>` starts at that hour unless `?time=` is given.
Views without one leave the time alone (London's "Tower Bridge at night", "The Thames at dusk").

## Modules

| Module | Owns | Exports |
|---|---|---|
| `index.html` | the page: CSS, menu markup, a script that writes the import map (three 0.186.1 from the CDN or `vendor/`, city.json `three`) and the modulepreloads, then imports `./engine/main.js` with a cache-busting query | — |
| `city.js` | `city.json` merged over `DEFAULTS`; the sun's position from the hour | `loadCity`, `DEFAULTS`, `sunAt`, `declinationOn` |
| `main.js` | renderer, scene, lights, haze, loading and streaming, render loop, AO and glow pipelines, shader preparation, background warm-up, change-of-light cover, stats, `window.__viewer`, filming hooks (`__viewer.film`: `frame()` draws one settled frame at once for a script's camera path, `setClock()` a virtual clock for waves and traffic, `prime()` streams and warms along a path, `hide()`; see `references/flythrough-video.md`) | — |
| `facade.js` | building material (the styles named in `tiles.json`, drawn from their data: `styles.js`; glass, landmark skins, night lights), city reflection probe | `createFacadeMaterial`, `createCityReflection` |
| `facade/core.js`, `facade/roofs.js` | the facade's core features, one implementation each (rustication, brick courses, shopfronts with boards, letters, pilasters and risers, the cornice's shadow, bands' placing, window coordinates for the glazing types; shared float constants and node helpers) and the roofs (roof codes, tones, zinc, slate, tile, variety, flat tops, brisis and dormers), built from the style data by `facade.js` | `float`, `shopfront`, `rusticJoints`, `brickCourses`, `corniceShadow`, ..., `roofLook` |
| `styles.js`, `styles/*.json` | facade styles as data: the viewer presets (`china-south`, `us-northeast`, `europe-west`, `uk-london`, `de-berlin`; `base` and `replace` as the pipeline's presets; also `hk-hongkong`, `sg-singapore`, `jp-tokyo`), city.json's changes over them, resolved per style of `tiles.json` | `loadPreset`, `resolveStyles`, `describe` |
| `ground.js` | land, green, aeroway, road, bridge, markings, mudflat, backdrop materials, street lighting | `createGroundMaterials` |
| `water.js` | sea and inland water, shore field, planar mirror, wave motion | `configureWater`, `createSeaMaterial`, `createInlandWaterMaterial`, `shoreField`, `renderWaterReflection`, `setWaterReflection`, `waterInView`, `setWaterTime` |
| `lattice.js` | open iron lattices (`[[structures]]` `lattice_tower`, the Eiffel Tower): the tile's `lattice` mesh, flat panels cut out by a box-filtered bar pattern (uv = pattern coordinates, colour alpha = pattern kind: 0 braced panels, 1 spandrel ornament, 2 railings, 3 glazing: light members over panes at 45 % opacity, 4 fabric: a membrane at 62 % with thin cables, both from a figure's `glazing` sheets); blended without depth writes, no shadow, out of the AO pre-pass; one draw call per tile; the pattern's coverage settles to its mean density with distance (no shimmer at dpr 1 or 2, WebGPU and WebGL 2) | `createLatticeMaterial` |
| `shores.js` | strips along land/water edges and pools | `loadShores` |
| `trees.js` | leaf atlas, seven species, impostors, streaming, instancing, far carpet | `createTrees` |
| `cars.js` | vehicle models by type name, lanes, parked cars, planar shadows | `createCars` |
| `rooftops.js` | rooftop items (five prototypes), parapets | `createRooftops` |
| `terrain.js` | ground height lookups on the TIN | `loadTerrain` |
| `night.js` | dusk and night sky, moon, the lights' schedule, lit material copies | `createNight` |
| `lamps.js` | real street lamps from a lighting inventory (06e_lamps: `web/lamps`): per lamp a pool of light on the street and its head's glow, instanced per 2 km chunk, drawn additively and only after dark; the inventory's coverage mask, which leaves out the ground's procedural posts there | `loadLamps`, `createLamps` |
| `ui.js` | the menu | `createMenu` |

Imports inside the engine are relative. `index.html` imports `./engine/main.js?v=<now>` and `main.js` imports every
sibling with its own query string (`./x.js${new URL(import.meta.url).search}`), so a plain reload runs the current
code; only `index.html` itself needs a hard reload after it changes. The page, `city.json` and the data links are
resolved against the page's URL (the city's folder), the modules against the engine's.

## city.json

Every key is optional: `city.json` is merged over `DEFAULTS` in `city.js` key by key (objects all the way down;
arrays and plain values replace the default), so a city lists what differs. A missing `city.json` runs on the
defaults with a console warning. Colours are linear RGB in 0..1 (HDR for the haze). Hours are local solar time.

| Key | Default | What it is |
|---|---|---|
| `title` | `"3D city"` | page title; the menu's title (after `nativeTitle`) |
| `nativeTitle` | `""` | the name in the city's own script, shown first in the menu (`深圳西部 · West Shenzhen 3D`) |
| `startViewPortrait` | `null` | the preset a portrait screen (taller than 1.2 × its width: a phone held upright) opens at instead of `startView` (`?view=` wins); `null`: `startView` everywhere. London: a view further back, so the skyline stays in the narrow frame |
| `startView` | `null` | the preset (by name, from `tiles.json`) the viewer opens at; `?view=` wins; `null`: the first preset. Paris: the Île de la Cité, while the menu lists the overview first (it would wait for the whole city) |
| `about` | `""` | the menu's About text (plain text): what is real, what is invented, credits and licences |
| `attribution` | `""` | an always-visible credit line, a small semi-transparent strip bottom right (clear of the stats line, the menu button and the streaming bar; wraps to a few lines at 360 px): plain text, `[label](https://url)` for a link (new tab) and `[label](#about)` for one that opens the menu's About; anything else is shown as text, never parsed as HTML. `""`: no line. **A choice to make per project:** the licences of most map data ask for credit where the map is seen (OSMF's attribution guidelines for interactive maps; ODbL §4.3; several national data licences), which a corner line satisfies; against it, a clean, uncluttered view, with full credits one click away in About. ## The first minute: shader preparation, changes of light, a lost GPU

Every city, both backends (main.js, "shaders without stalls"; the lessons in
`../../references/performance-and-loading.md` section 12):

- **Background warm-up order**: the day's remaining passes (the moving frames), the sky map, then the night's and
  dusk's *settled* passes (glass's probe, the water's mirror, the occlusion pipeline with its glow, the still glow),
  moonlight before dusk, then their moving passes. It pauses while the view moves, while a change of light is held,
  and for 1 s after any input (a drag, a zoom, a click, the time slider).
- **WebGL 2: one program at a time while the page is used, batches while it is idle.** A held change of light's
  round and a drawn frame each ask for at most one new program (`?glLinks=<n>`; a held round up to four where the
  driver compiles in the background), none while one is still compiling in the driver (KHR_parallel_shader_compile)
  and none while the GPU is still on an earlier frame (a link, a change of resolution or a redraw then waits without
  blocking the page). Without KHR_parallel_shader_compile (Chrome's ANGLE on Vulkan) three compiles and links every
  program at once on the main thread; there a background warm-up round with no input for 1 s, nothing on the GPU and
  no change of light held links up to 8 programs or 20 ms of linking (`?warmLinks=`, `?warmLinkMs=`), builds for
  60 ms counted from the round's start (`?warmMs=`), links a material whose build ends past 60 ms of the round in the
  next round (`?warmSplit=`: a Berlin facade is ~175 ms to build and ~60 to link) and comes 40 ms after the last one
  began (`?warmGap=`; `?warmLinks=1`: one link a round every 100 ms, as before). A link that took under 3 ms (a
  program the driver already had) counts against no limit. WebGPU: no limit, its pace unchanged.
- **Nothing built twice for nothing.** The SSAO and the bloom are set up once (three's `SSAONode.setup` ran again
  for every material built that samples the occlusion and gave its quads new programs each time: Berlin's warm-up
  linked the same two SSAO programs 200 times), and the pre-pass and the SSAO draw under the renderer's own context
  node whoever asks for them first. The backdrop and the town layer build only the paths the city uses (`area` in
  `createGroundMaterials`, from tiles.json): without land cover maps and block masses (New York, Shenzhen) their
  shaders are a quarter of the nodes, ~140 -> ~45 ms of node building per pass and light; with masses (Paris, London,
  Berlin) the town layer's painted-block path is left out; the backdrop of a city with cover maps keeps both (the
  maps arrive after the first frame).
- **Glass's city probe is prepared before its first capture** (`loading.passesLater`): its passes, the sun's shadow map
  drawn inside it too, are built without drawing once the view is up, and the first capture waits for them (glass
  reflects the sky meanwhile); captured at once, it built them in the second frame on screen (Berlin, a 305 ms task).
- **A change of light held under the cover is prepared, not drawn**: while the view is still, the frames under the
  cover are replaced by rounds that build the view's passes without drawing (`compileOnly`, ~60 ms each,
  `loading.holdBuildMs` if larger), and the frame is drawn once a round finds nothing left and its pipelines are
  ready. `?heldprep=0`: the old way (frames drawn under the cover, BUILD_MS of building each). On WebGL 2 with
  `KHR_parallel_shader_compile` the next held round runs as soon as fewer than 4 programs (`?heldLinks=`) are still
  compiling, rather than once all of the last round's are: the driver's queue kept full (`?heldfill=0`: as before).
  While the time slider is still being dragged under the cover nothing is drawn or prepared; 250 ms after its last
  input the held rounds prepare the light it landed on, not each light it passed (`?timerest=0`: as before). Both
  change only when the work is done (Singapore M9 fix round 1; the same pictures, pixdiff New York and Shenzhen).
  The frame is drawn at the animation frame after the last held round, not in the same one: that round ran the sun's
  shadow node, and three draws a shadow map at most once per animation frame, so the first frame of the new light
  came out complete and uncovered with no fresh shadows, the towers' shadows popping in with the next
  (`?heldnext=0`: as before). The slider's rest rule is checked before the moving frames' branch (after it, each tick
  of a drag under the cover resized the canvas twice). (Singapore M9 fix, WebGL 2 light-change regressions.)
- **The sky map** (PMREM of the sky) is made once before the next frame, not on every change of the hour: the time
  slider sent ~60 renders a second ahead of any frame.
- **A lost GPU** (WebGL 2's context or WebGPU's device, other than by leaving the page) shows "The graphics card
  stopped responding." with a Reload button instead of a frozen picture; `__viewer.lost()` returns its info.
- Measuring: `?warmlog=1` keeps `__viewer.warmLog` (each program asked for and linked with its time, warm-up and
  held rounds, the lazy frames' new pipelines, changes of light); read it over CDP (`scripts/cdp.mjs eval`) with the long tasks
  and the frame log (`__viewer.frames()`), and fail a run that lost the GPU or drew nothing.

## Libraries in the code (started in Shenzhen, extended per city)

These are libraries the data picks from rather than settings; a city that needs others extends the module:

- **Tree species** (`trees.js`): banyan, camphor-like broadleaf, acacia, flowering Bauhinia/flame tree, mangrove,
  royal and coconut palm, their leaf atlas and models, and the street-tree species mapping of 08_trees.py's codes.
  Temperate cities (plane, lime, oak; leafless in winter) need species of their own.
- **Vehicle models** (`cars.js`) by type name: sedan, suv, taxi (a roof sign), van, bus, truck, lorry; a type of
  another name is drawn as a sedan. Double-deckers or a London cab need a model.
- **Rooftop items** (`rooftops.js`): the materials `rooftops.json` names (water tanks, solar heaters, sheds...).
- **Facade styles** (`facade.js`, their data in `styles/<preset>.json`, `styles.js`): per style of `tiles.json` its
  bay width, window box, shop share, air conditioners, groups and features, from the city's preset
  (`facade.preset`) and its changes (`facade.styles`); the shader is built only from the features the city's styles
  use: each feature (`facade/core.js`, keys in `styles.js`) only when one of its styles lists it, the wall's
  features in a slot by the style's `fade` (none: on the wall itself, as Paris's; 'none': a branch over the whole
  wall, London's; 'bays': a branch faded with the bays, Berlin's), each slot's layers in a fixed order.
  Root preset `china-south`: `glass`, `residential`, `village`, `factory`, `commercial`, `civic`, `plain`
  and the landmark skins `fins`, `bands`, `lattice`, `honeycomb`, `panel`; a style no preset knows gets the defaults. New York's add
  `brownstone`, `brick`, `stone`, `castiron`, `signs`; Paris's (europe-west, M4) `haussmann` (cut stone, rusticated
  ground floor and entresol, continuous iron balconies on the 2nd and 5th floors, guard rails on the other French
  windows, shops), `faubourg` and `house` (plaster, shutters), `limestone` (palaces and monuments: 4.5 m floors,
  deep cornice), `brickstone` (brick with stone bands, surrounds and quoins), `hbm` (brick with concrete bands),
  `postwar`, `modern`, `concretepanel` (piers and window strips, dark spandrels on some), `shed`.
- **Roofs** (`facade.js`, from 06_tiles' roof code in `TEXCOORD_2.y` = rise + 8 x material, `uvRange.base[1]`):
  walls, floors and cornice stop at the eaves (height less the rise); a mansard's steep brisis (normal.y under
  0.55) is zinc, or slate on `brickstone`, with dormers (every bay on stone blocks, every other bay elsewhere); a
  pitched roof is zinc or terracotta tile; flat tops by material (1 zinc, 2 tile, 3 or 0: `facade.roofs.tones`);
  walls above the eaves are blind party gables. A city without the code (0) keeps flat roofs as before.
- **Look tuning** that never needed a setting: ground paving and soil colours, mudflats, shores, night sky
  colours, street-lamp spacing, obstruction lights over 150 m.
